# Internationalization (i18n)

Idéfix ships fully translated UI chrome across **six locales**. This is enforced,
not aspirational: a locale that drops a string fails the `typecheck` CI job
(`npm run build` itself runs `vite build` without `tsc`).

## Locales

| Code    | Language        | Notes                                    |
|---------|-----------------|------------------------------------------|
| `fr`    | Français        | **Source** locale — keys authored here   |
| `en-GB` | English         |                                          |
| `es`    | Español         |                                          |
| `nl`    | Nederlands      |                                          |
| `de`    | Deutsch         | longest-text stress case                 |
| `lb`    | Lëtzebuergesch  | ⚠ **needs human review** (see below)     |

Fallback chain: `lb → de → fr`, everything else `→ fr`. Wired in
[`src/state/i18n.ts`](../../webapp/src/state/i18n.ts).

## How it works

- Library: **i18next / react-i18next** (works in Vite; `next-intl` is Next.js-only
  and is deliberately *not* used here).
- Keys are flat dotted strings (`gate.title`), source of truth is
  [`fr.ts`](../../webapp/src/state/locales/fr.ts). It exports the `Messages` type;
  every other locale is typed `: Messages`, so **a missing key fails `tsc`**.
- Interpolation uses i18next `{{placeholder}}` tokens. Never assemble a sentence
  by concatenation — one key with placeholders instead.

## Enforcement (the point)

| Gate                  | Catches                                                        |
|-----------------------|---------------------------------------------------------------|
| `tsc --noEmit`        | missing/extra keys (compiler, `Messages` type)                |
| `npm run i18n:parity` | empty / `__MISSING__` values, `{{placeholder}}` drift         |
| `npm run ui:contract` | seven UI rules, among them the logo asset used outside `BrandMark` and the brand and signature presence; a ratchet against `webapp/ui-contract-baseline.json` |

`i18n:parity` runs in CI as a **blocking** job ([ui-gate.yml](../../.github/workflows/ui-gate.yml)).

## Adding a key

1. Add it to `fr.ts` (source).
2. `tsc` will now fail every other locale until the key is added there too.
3. Add the translation in `en/es/nl/de/lb`. Run `npm run i18n:parity`.

## Luxembourgish (`lb`) — review status

`lb` has thin coverage in the Unicode Common Locale Data Repository (CLDR) and
in machine translation. The committed `lb.ts` is a **best-effort machine
draft** and is flagged in-file (`⚠ HUMAN-REVIEW ERFUERDERLECH`). It carries
non-empty values so the completeness gate passes, but the strings should be
reviewed by a human Luxembourgish speaker before being treated as final. Do not
assume `lb` quality matches the other five locales yet.

## Not translated (by design)

Editorial/data content — mission labels, methodology prose, channel handles,
raw enum values (archetype, credibility) — stays in French on the data side.
Only UI *chrome* is translated. The author **name** in the signature is a proper
noun and is not translated; its **role** label is (`signature.role`).
